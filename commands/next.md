착수할 항목: `$ARGUMENTS` (비어 있으면 후보를 골라 준다)

이 커맨드는 **고르는 것까지**가 일이고, 그다음 착수·보고 규칙은 `board` 스킬에 있다.
규칙을 여기 복사하지 말고 그 스킬을 로드해 따른다.

## 절차

### 1. 인자가 있으면 픽커를 건너뛴다

`$ARGUMENTS` 에 참조(`rocky-12` / `12` / raw id)가 들어 있으면 그건 "이 항목을 맡아라" 다 —
바로 4번으로 간다. 참조가 아닌 문장이면(예: "p1 만") 후보를 좁히는 조건으로 읽는다.

### 2. 후보 조회

```bash
rocky-todo next --json          # cwd 의 git repo 이름으로 보드 유추, 상위 8개
```

- 후보가 0건이면 `rocky-todo next --json --all` 로 한 번 더 — 이 레포에 보드가 없을 수 있다.
- `rocky-todo` 가 없거나 데몬이 안 뜨면 MCP `todo_list { board }` 로 폴백해 직접 랭킹한다.
  이때 **"주인 없는 진행중" 판정은 못 한다** — `doingState` 는 REST 응답에만 실린다. 그 경우
  랭킹이 거칠어졌다는 사실을 한 줄로 밝힌다. 데몬이 아예 안 뜨면 가짜 목록을 만들지 말고
  `rocky-todo daemon status` 를 안내하고 멈춘다.

랭킹 기준은 `src/next.ts` 에 있다(주인 없는 doing → 마감 → 우선순위 → 최근 댓글, 우산 항목
제외). 여기서 다시 정렬하지 않는다 — 받은 순서가 곧 순위다.

### 3. 받은 후보를 전부 보여준다

한 줄씩 `ref · 제목 · 근거`. 선택지 UI 에는 4개만 올라가므로, **무엇이 밀려났는지**는 이
목록에서만 보인다. 생략하지 않는다.

### 4. AskUserQuestion 으로 고르게 한다

- 질문 하나, `multiSelect: false`, header 는 `다음 작업`.
- 옵션은 **상위 4개**. `label` 은 `ref` + 제목 앞부분(짧게), `description` 은 근거와 "이게
  무슨 일인지" 한 줄. 근거는 CLI 가 준 문구를 그대로 쓴다.
- 자동으로 붙는 "Other" 가 곧 "목록의 다른 항목" 이다 — 사용자가 `rocky-todo-19` 처럼
  참조를 직접 적을 수 있다고 옵션 설명이나 직전 문장에서 알려 준다.
- 후보가 1건뿐이면 묻지 말고 그 항목으로 간다.

### 5. 고른 항목을 읽는다

`todo_list { id: "<ref>" }` 로 상세 + 히스토리 + 댓글을 읽는다. 진행중이던 항목을 이어받는
경우(`이어받기(…)` 근거)에는 **어디까지 됐는지 먼저 요약**하고 시작한다 — 히스토리와 댓글이
그 정보의 유일한 출처다.

읽어도 무엇을 원하는지 모호하면 `start` 전에 묻는다. `start` 는 "지금 내가 잡고 있다" 는
신호라 되돌리는 비용이 있다.

### 6. 어디서 할지 — 보드가 이 레포가 아닐 때만 묻는다

고른 항목의 보드가 cwd 의 레포와 같으면 **묻지 않고 여기서 한다**. 다르면 AskUserQuestion 을
한 번 더 띄운다:

- `여기서 진행` — 다른 레포 항목을 이 세션에서 다룬다(문서·조사처럼 코드를 안 건드릴 때).
- `새 세션 띄우기` — `rocky-todo spawn <ref>`. 그 todo 전용 워크트리에서 백그라운드로 돈다.
- `다른 세션에 넘기기` — `rocky-todo sessions` 로 후보를 보고 `rocky-todo handoff <ref> --session <name>`.

spawn/handoff 를 골랐으면 이 세션은 결과 위치만 한두 줄로 보고하고 끝낸다 — 그 작업을 여기서
같이 하지 않는다.

### 7. 착수

`board` 스킬의 에티켓을 따른다 — `todo_status { action: "start", actor: "claude-code" }` 로
표시하고 시작, 진행 보고는 `comment`, 끝나면 `done`.

## 하지 않는 것

- 후보를 고른 것으로 `done`/`archive` 를 하지 않는다. 이 커맨드는 착수까지다.
- 한 번에 두 건 이상 `start` 하지 않는다. 여러 건을 하고 싶다는 요청이면 순서만 정해 주고
  첫 건만 start 한다.
- 후보가 없으면 새 todo 를 만들어 채우지 않는다. "열린 항목이 없다" 를 그대로 보고한다.
